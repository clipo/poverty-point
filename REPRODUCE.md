# Reproducibility Guide

Step-by-step instructions for regenerating every analysis, simulation, and figure in the manuscripts. All stochastic simulations use deterministic seeds; running the canonical commands below should produce numerically identical outputs to those reported in the manuscript and supplemental.

## 1. Environment

Tested on macOS 25.5 (Darwin) with Python 3.12.2.

```bash
# Option A: pip + venv (pure-Python paths)
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

```bash
# Option B: conda (recommended for geospatial stack on macOS / Windows)
conda create -n pp-signaling python=3.12 -c conda-forge \
    numpy=2.4.3 scipy=1.17.1 pandas=3.0.1 matplotlib=3.10.8 \
    seaborn=0.13.2 networkx=3.3 cartopy=0.25.0 geopandas=1.1.0 \
    shapely=2.1.1 pyproj=3.6.1 rasterio=1.4.2 \
    python-docx=1.1.0 pyyaml=6.0.1 tqdm=4.66.5
conda activate pp-signaling
```

`pandoc` (>= 3.0) is required for the manuscript docx build step; install via `brew install pandoc` on macOS or your OS package manager.

```bash
# Option C: Container (Docker / Podman / Apptainer) — recommended for a
#           clean-room rebuild on any platform. Bundles Python 3.12.2, the
#           pinned dependencies, pandoc, and the figure fonts. No host setup
#           beyond a container runtime. See "Reproducing in a container" below.
docker build -t poverty-point .
docker run --rm -v "$PWD/figures:/opt/poverty-point/figures" poverty-point make figures
```

### Reproducing in a container

The repository ships a `Dockerfile` that builds a fully self-contained environment, which avoids the GEOS/PROJ/GDAL toolchain issues that make cartopy and geopandas hard to install natively.

```bash
# Build the image (~5-10 min on first build; caches afterwards)
docker build -t poverty-point .

# Regenerate every figure; outputs are written back to the host figures/ tree
docker run --rm -v "$PWD/figures:/opt/poverty-point/figures" poverty-point make figures

# Full rebuild (analyses + figures + manuscript docx); mount the dirs you want updated
docker run --rm \
    -v "$PWD/figures:/opt/poverty-point/figures" \
    -v "$PWD/results:/opt/poverty-point/results" \
    -v "$PWD/docs:/opt/poverty-point/docs" \
    poverty-point make all

# Interactive shell inside the container
docker run --rm -it poverty-point bash
```

On HPC systems without Docker, use Podman (rootless) to build, or convert a Docker image to a Singularity Image File for Apptainer:

```bash
podman build -t poverty-point .                                    # rootless build
apptainer build poverty-point.sif docker-daemon://poverty-point:latest
apptainer exec --bind "$PWD/figures:/opt/poverty-point/figures" poverty-point.sif make figures
```

Notes:

- The first figure run downloads a few megabytes of Natural Earth basemap data into cartopy's cache (Figure 1), so it needs network access on first use; the bundled Saucier geomorphology and EPA ecoregion shapefiles in `data/` are used directly.
- Figures target Times New Roman / Arial. The image installs these via `ttf-mscorefonts-installer` when the build host has network; otherwise it falls back to the metric-compatible Liberation fonts, which changes glyph rendering only, not the data.
- Figure 2 in the manuscript is an externally provided labeled LiDAR digital elevation model (Diana Greenlee, Poverty Point Station Archaeology Program) shipped at `figures/manuscript/figure_02_site_architecture.png`. It is **not** regenerated by `make figures`; the `create_figure_02_site_architecture.py` step formats a separate, unlabeled LiDAR base image into `figures/final/` for reference only. Every other manuscript figure is reproduced from its `create_figure_NN_*.py` script, named to match the figure number it produces.

Two external geospatial datasets are referenced by Figure 1 and the GIS-ε analyses. The repo expects them at the paths below; the scripts will fail with informative errors if they are missing.

| Dataset | Repo path | Source |

## 3. Random-seed strategy

All stochastic simulations are seeded deterministically with `np.random.default_rng(seed)`.

- Calibration replicates: `scripts/analysis/run_calibration_replicates.py` uses `seed = 1000 + replicate_index`.
- Ablation sweep: `scripts/analysis/signal_conditional_ablation_sweep.py` derives each cell's seed from the replicate index, the mode, and the sigma target.
- Phase-space, ensemble, and Price-decomposition scripts each document their seed formulas at the top of the file.
- Table 2 Monte Carlo: `scripts/analysis/table2_weight_perturbation.py` uses `default_rng(42)`.

Re-running any of the scripts below should produce numerically identical outputs to those checked into `results/`.

## 4. Reproduce the analyses

### 4.1 Deterministic analyses (minutes)

```bash
make analyses
```

Runs, in order: the analytical diagnostics (`verify_analytical_diagnostics.py`: fixed-point convergence in exactly 18 iterations across a 30-point sigma sweep, multi-start uniqueness of the equilibrium monument stock, single-crossing verification, reference-window invariance), the OAT sensitivity table, the three GIS-ε scripts (Saucier geomorphic, EPA Level IV, broad-category), the paleoclimate σ comparison, the water-route catchment ε, the partial-correlation decomposition (Table 3), the predicted scale ratios, per-event labor scaling (the §6.3 α sweep), the two phenology tests, the Table 2 weight-perturbation Monte Carlo (§S13), the exotic posterior-predictive check (§6.1: per-material intervals, z-scores, Mahalanobis d²), the hydrograph covariance analysis (§6.5), the renovation ratio (§6.8), and the tier-3 extensions.

Key checks against committed outputs:

- `results/sensitivity/analytical_diagnostics.json`: all four diagnostics pass.
- `results/gis/gis_epsilon_results.json`: Spearman ρ = 0.70 (p = 0.016) between qualitative ε and Saucier-geomorphic ε across the 11 LMV sites (corrected coastal coding).
- `results/gis/gis_epsilon_eparegions.json`: ρ = 0.12 (p = 0.73) between qualitative ε and EPA-L4 ε.
- `results/sensitivity/partial_correlation_eps_nagg.json`: every Table 3 cell.
- `results/sensitivity/per_event_labor_scaling.json`: best-calibrated α = 2.0; Watson Brake 0.91× at α = 2, 2.84× at α = 1.
- `results/calibration_replicates/exotic_ppc.json`: the §6.1 per-material comparison and joint Mahalanobis d².

### 4.2 Stochastic simulation suite (~2-3 hours)

```bash
make simulations
```

Runs, in order: the calibration replicates (4 scenarios × 8 replicates × 200 years; §S7.2 and the §6.1 anchor), the Figure 8 ensemble (5 replicates × 500 years), the Price decomposition (§S5.5), the signal-conditional ablation sweep (7 σ targets × 20 replicates × 2 modes × 200 years; §4.1/§4.3 and §S7.1), the replicated phase space (12×10 grid × 5 replicates × 300 years; §4.2), the factorial channel ablation (§S5.4), and the Morris sensitivity screen.

The §4/§S7 tables in the manuscript are regenerated from these outputs; the committed JSONs in `results/` are the runs reported in the current draft.

## 5. Regenerate the figures

```bash
make figures
```

Each figure script is independent and named to match the figure it produces (see `scripts/figure_generation/README.md` for the full mapping). Simulation-dependent figures (7, 8, 9, 12, S6, S7, S8) read the outputs of `make simulations`; the rest are self-contained.

## 6. Build the manuscript docx files

The active draft is the merged JAMT manuscript at `docs/jamt/Manuscript.md` and `docs/jamt/Supplemental.md`. Run `make manuscript` from the project root to rebuild both, or invoke pandoc directly:

```bash
pandoc docs/jamt/Manuscript.md \
    -o docs/jamt/Manuscript.docx \
    --reference-doc docs/jamt/reference_template.docx \
    --resource-path docs/jamt \
    --from markdown --to docx

pandoc docs/jamt/Supplemental.md \
    -o docs/jamt/Supplemental.docx \
    --reference-doc docs/jamt/reference_template.docx \
    --resource-path docs/jamt \
    --from markdown --to docx
```

The reference template `docs/jamt/reference_template.docx` controls Times New Roman 11pt, italic figure captions, and other manuscript conventions per the project CLAUDE.md.

## 7. Verifying reproduction

Each analysis writes a JSON or CSV result file under `results/`. Comparing your re-run output against the committed file in git (`git diff results/...`) should show no numerical changes if your environment matches the pinned versions in `requirements.txt`. Small floating-point differences (last 2-3 decimal places) can occur across BLAS implementations; the qualitative results in the manuscript are robust to this level of variation.

## 8. Provenance notes

- The agent-based engine (`src/poverty_point/integrated_simulation.py`) was revised in August 2026 to implement the ODD specification exactly (once-per-year scheduling, band fission and dissolution, heterogeneous band quality, realized network vulnerability, monument signal-stock depreciation, density-dependent harvests). All committed simulation outputs postdate that revision; earlier outputs are recoverable from git history but do not correspond to the current engine.
- The regime-switching simulation, per-event labor scaling, signal-conditional partner formation, the restructured network-saturation function, and the water-route catchment ε are all implemented in this release (`scripts/analysis/`); the regional spatially explicit model with hydrographic routing remains a minimal implementation (`regional_band_allocation.py`).
- `tests/` carries the full unit and integration suite (`python -m pytest tests/ -q`).
